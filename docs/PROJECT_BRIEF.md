# Sika Time Tracker：产品与技术方案（草案）

## 1. 产品目标

Sika Time Tracker 是一款个人使用的 Windows 桌面应用。它在后台自动记录当前活跃窗口，将活动按用户定义的规则归类，并通过贡献热力图和每日时间轴帮助用户回顾时间投入。

核心原则：

- 自动记录，尽量不打扰用户。
- 数据默认仅保存在本机，不上传窗口标题等隐私信息。
- 分类规则透明、可编辑，并允许历史数据重新分类。
- 界面采用 Fluent Design 2.0，支持浅色、深色和跟随系统主题。

## 2. 第一版功能范围（MVP）

### 2.1 活跃窗口追踪

- 应用启动后在后台追踪 Windows 当前前台窗口。
- 每次前台窗口发生变化时，记录：
  - 进程名称；
  - 窗口标题；
  - 活动开始和结束时间；
  - 对应分类。
- 相邻且属于同一窗口的短间隔记录可自动合并，减少碎片数据。
- 启动后始终自动追踪，不提供手动暂停入口；左下角实时显示当前前台软件、窗口标题和本次连续追踪时长。
- 追踪状态使用颜色区分：绿色表示正在追踪，红色表示 AFK，灰色表示锁屏、休眠或内部配置更新，蓝色表示运行正常但当前窗口不计入或正在等待窗口。
- 可选“空闲检测”：键鼠无操作达到设定时长后停止累计；恢复操作时重新开始记录。
- 电脑锁屏、睡眠、休眠或切换到其他用户会话时，必须立即结束当前活动段并停止累计。
- 唤醒后仍处于锁屏状态时不得恢复统计；只有用户解锁且检测到有效前台窗口后才开始新的活动段。
- 应用异常退出或电脑关机时，尽量在下次启动时修正未结束的记录，避免产生超长活动段。

### 2.2 分类规则

- 用户可创建分类，例如“工作”“游戏”“其他”，并自定义名称、颜色和排序。
- 规则可匹配窗口标题或进程名称，支持：
  - 普通文本包含；
  - 正则表达式；
  - 忽略大小写。
- 规则按优先级从高到低匹配，首个命中的规则决定分类。
- 未命中的活动进入默认分类“其他”。
- 编辑规则后，可选择对历史记录重新分类；原始窗口信息不被修改。
- 设置界面应提供规则测试，展示示例文本是否命中及正则错误。

### 2.3 数据展示

主页面包含：

- 日期范围和分类筛选；
- 类似 GitHub 贡献图的年度热力图；
- 汇总数据，例如所选分类总时长、日均时长和最活跃日期。

热力图设计：

- 每个方块代表一天，颜色深浅表示该日所选活动的累计时长；
- 支持选择单个分类、多个分类或全部活动；
- 悬停显示日期、总时长和主要分类；
- 点击某一天进入该日详情。

每日详情：

- 以 00:00–24:00 的纵向或横向时间轴展示活动段；
- 不同分类使用对应颜色；
- 点击活动段可查看开始时间、结束时间、持续时长、进程与窗口标题；
- 支持按分类过滤，并可手动修正单条记录的分类。

### 2.4 设置

- 开机自启动；
- 启动后最小化到系统托盘；
- 空闲检测开关与空闲阈值；
- 最短记录时长与相邻记录合并间隔；
- 浅色、深色、跟随系统主题；
- 分类及正则规则管理；
- 数据库位置、数据导出与数据清理；
- 隐私选项：可配置不记录窗口标题，仅记录进程名称。

## 3. 交互与界面结构

采用 Fluent Design 2.0 风格，使用左侧导航：

1. **活动**：顶部显示筛选器与时间汇总，中部显示热力图，下部显示当前选中日期的活动时间轴。点击热力图日期后直接更新下方时间轴，不切换页面。
2. **分类规则**：分类、颜色、优先级和规则测试。
3. **设置**：启动、追踪、外观、数据和隐私选项。

活动页默认选中今天。点击时间轴记录时，在右侧详情面板中显示完整信息并允许手动修正分类。

系统托盘菜单仅提供“打开主窗口”和“退出”。后台运行时不应持续占用任务栏位置，追踪始终自动进行。

任务栏左侧空白区显示本周“工作”分类累计时长。该标签是无边框、置顶且不占用任务切换器的独立窗口，按系统报告的任务栏矩形与 DPI 自适应定位；任务栏尺寸、方向或显示缩放变化后自动重新布局，点击标签打开主窗口，全屏应用和自动隐藏任务栏收起时隐藏标签。

## 4. 推荐技术方案

- **平台**：Windows 10/11，优先适配 Windows 11。
- **开发框架**：C#、.NET 10、WinUI 3（Windows App SDK）。
- **设计体系**：WinUI 原生控件与 Fluent Design 2.0 视觉规范。
- **数据存储**：SQLite；通过 Entity Framework Core 或轻量数据访问层管理。
- **窗口检测**：Win32 API（如前台窗口句柄、窗口标题和所属进程查询）。
- **架构**：MVVM；追踪服务、分类服务、统计服务和 UI 分离。
- **日志**：仅记录运行错误和诊断信息，不在日志中写入敏感窗口标题。
- **发布方式**：不制作安装包；发布为 unpackaged、self-contained 的便携版可执行文件，用户直接双击 `SikaTimeTracker.exe` 运行，目标电脑无需另行安装 Windows App SDK。

推荐后台采集方式为事件驱动监听前台窗口变化，并使用低频校验定时器补偿遗漏；这比持续高频轮询更省资源。

## 5. 初步数据模型

### ActivitySegment（活动记录）

- `Id`
- `StartTimeUtc`
- `EndTimeUtc`
- `ProcessName`
- `WindowTitle`
- `CategoryId`
- `ClassificationRuleId`（可为空）
- `IsManuallyClassified`
- `CreatedAtUtc`

### Category（分类）

- `Id`
- `Name`
- `Color`
- `SortOrder`
- `IsDefault`

### ClassificationRule（分类规则）

- `Id`
- `CategoryId`
- `Target`（进程名、窗口标题或两者）
- `MatchType`（包含或正则）
- `Pattern`
- `IgnoreCase`
- `Priority`
- `IsEnabled`

### AppSetting（设置）

- `Key`
- `Value`

时间统一以 UTC 存储，展示和按天统计时转换到本地时区，以降低夏令时或时区变化带来的问题。

## 6. 关键行为约定

- 统计时长按活动段与当天边界的交集计算，跨午夜记录会正确拆分到两天。
- 手动分类优先于自动规则，重新分类时不覆盖手动结果。
- 正则表达式需要超时保护，避免复杂表达式拖慢后台追踪。
- 监听 Windows 会话状态变化：锁屏、注销、断开会话或切换用户时，立即关闭当前活动段并进入暂停状态。
- 监听 Windows 电源状态变化：睡眠或休眠前立即关闭当前活动段；从睡眠或休眠恢复时不补记离线时段。
- 唤醒事件和解锁事件分别处理：电脑已唤醒但尚未解锁时，仍保持暂停。
- 解锁后重新读取前台窗口，从解锁后的实际检测时刻创建新活动段，不延续锁屏前的记录。
- 使用低频健康检查比较系统单调时钟与记录状态；如果系统事件因现代待机、崩溃等原因漏报，并发现异常时间跳跃，则在跳跃前截断活动段，禁止生成覆盖整段睡眠时间的记录。
- 应用启动时清理数据库中未正常结束的活动段，按最后一次可信心跳时间截断，而不是以本次启动时间作为结束时间。
- 锁屏、睡眠、关机和非当前用户会话期间一律不累计活动时间。
- 开机自启动可关闭，卸载应用时应清理对应启动项。

## 7. 暂不包含在第一版

- 多设备同步和云端账户；
- 团队管理、考勤或雇员监控；
- 截图、键盘内容或网页内容采集；
- 移动端和 macOS 支持；
- 自动生成生产力评分。

## 8. MVP 验收标准

- 连续运行 8 小时后仍能稳定记录窗口切换，且没有明显影响日常使用。
- 记录可在应用重启后完整读取。
- 用户能创建、排序和测试分类规则，活动能按优先级正确归类。
- 热力图能按日期和分类显示累计时长，点击日期可打开当天时间轴。
- 暂停、空闲、锁屏和睡眠期间不产生错误累计。
- 分别验证锁屏/解锁、睡眠/唤醒、休眠/恢复、切换用户和现代待机；任一场景恢复后，时间轴中均不得出现覆盖非活跃期间的活动段。
- 唤醒但未解锁期间保持零累计，解锁后从新的前台窗口检测时刻重新开始。
- 模拟应用被强制结束后重新启动，未结束记录不得延伸到重启时刻。
- 开机自启动、托盘运行、主题和隐私设置均能正常保存并生效。
- 窗口标题与活动数据不会在未经用户明确操作的情况下离开本机。

## 9. 建议实施顺序

1. 搭建 WinUI 3 应用、SQLite 数据层和基础导航。
2. 实现前台窗口追踪、空闲/锁屏处理与活动段持久化。
3. 实现分类、正则规则、优先级和历史重新分类。
4. 实现概览统计、贡献热力图和每日时间轴。
5. 完成托盘、开机自启、设置、导出和隐私功能。
6. 做稳定性、性能、跨午夜与异常退出测试，并打包发布。

## 10. 实施前需要最终确认的默认值

- 默认空闲阈值：建议 5 分钟。
- 默认最短记录时长：建议 2 秒。
- 相邻同类记录合并间隔：建议 10 秒。
- 热力图强度：建议按固定时长分档，而不是按当前数据动态缩放，便于不同日期之间比较。
- 发布方式：免安装便携版 `SikaTimeTracker.exe`。采用 WinUI 3 支持的 single-file 自解压发布模式；首次运行时框架会将运行依赖释放到系统临时位置。
- 开机自启动：便携版通过当前用户启动项实现，并保存可执行文件的绝对路径；用户移动程序后需在设置中重新启用自启动。
